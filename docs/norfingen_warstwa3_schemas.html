Zasada VAT w Postingach

VAT nie jest osobnym postingiem — jest polem vatAmount na postingu debetowym. Konto 2770 zasilane jest przez Tripletex automatycznie.

Konto 2770 Skyldig merverdiavgift: Tripletex zasila je automatycznie na podstawie vatAmount. Generator nie tworzy ręcznie postingu na 2770. Rozliczane osobnym MANUAL Voucherem przy składaniu kwartalnej deklaracji MVA.
Zaokrąglenia: Generator oblicza round(netto × 0.25, 2) — nie odwrotnie z brutto. Tolerancja Tripletex: ±1 NOK.

Mapowanie pól subledgerowych

Pola customer, supplier, employee na Postingu — nie metadane. Tripletex używa ich do raportów wiekowania i kart pracowniczych. Bez nich postingi trafiają do ledgera, subledger pozostaje pusty.

Reguły walidacji

Cztery warunki sprawdzane przez generator przed każdym POST /v2/ledger/voucher.

# 1. Balans — suma amount wszystkich postingów = 0
assert sum(p.amount for p in postings) == 0, "Voucher niezbalansowany"

# 2. Minimum 2 postingi
assert len(postings) >= 2, "Voucher wymaga min. 2 postingów"

# 3. Każdy posting ma konto GL
assert all(p.account is not None for p in postings), "Brak konta GL w postingu"

# 4. Zgodność vatAmount ze stawką (tolerancja ±1 NOK)
if posting.vatType is not None:
    expected = round(amount_excl_vat * vat_rate, 2)
    assert abs(posting.vatAmount - expected) <= 1.0, "Niezgodność vatAmount"
